## Decisions

- Mirror Python's narrow precompute/inject estimator route. Do not add a metric
  field to the frozen `Problem` contract.
- Keep the separate public `dtwc.compute_distance_matrix` signature and
  behavior unchanged. F18 uses an estimator-internal routed MEX command; its
  focused matrix assertions are supplemental to the public estimator gate.
- Preserve lazy CPU-L1. Precompute once for CPU-SquaredL2 or GPU, outside
  `NInit`, and inject into every restart after all semantic setters.
- Reject metric/variant/missing/backend cross-products that would silently
  replace requested semantics.
- MATLAB estimator HPC has no transport. Explicit HPC must error before
  `dtwc.device` can inspect credentials or invoke SSH; active HPC must error
  without another transport attempt. The only decisive HPC process uses a
  repo-local recording `ssh.cmd`, never a network transport.
- The functional MATLAB `dtwc.cluster` path has the same device-routing defect
  but is a separate public entry point; F40 owns it.
- Nsight kernel evidence, not Env state or numerical parity alone, proves real
  CUDA estimator reachability.
- The ordinary five-suite gate runs only on the OpenMP/CUDA-OFF MEX. The CUDA
  MEX uses isolated profiles because two ordinary capability tests correctly
  expect GPU unavailable.
- A guarded source gate is the local Metal/layout arbiter. Real Metal estimator
  reachability remains F41 `[BLOCKED-ENV]`.
