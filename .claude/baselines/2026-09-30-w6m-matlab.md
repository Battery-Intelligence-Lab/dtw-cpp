## Decisions taken and left open

- An index below 1 is an error wherever `to_0based` runs, which includes the ARI/NMI label vectors and the dendrogram
  merge ids: `dtwc.adjusted_rand([0 0 1 1], ...)` raised nothing before and raises `dtwc:invalidArgument` now. C++ takes
  any int label; an alternative is to pass labels through unshifted (no `to_0based`, and `test_int_min_label_rejected`
  goes).
- `Problem_dist_by_ind` with an index above N returns 0 silently (probe on the step-1 MEX: (5,1), (1,5), (100,1) on N=4);
  `Problem::dist_by_ind` is unchecked by design. Not fixed here.
- `set_variant('msm'|'twe')` is accepted with default parameters; the MEX has no way to set `msm_c`, `twe_nu`, `twe_lambda`.
- `DTWClustering.resolve_metric` and `+distance/private/validate_metric.m` keep their own metric lists (`l1`,
  `squared_euclidean`[, `sqeuclidean`]); `parse_distance_strategy` stays (no C++ table).
- MATLAB `Problem` has no public read for band, verbose, max_iter or n_repetitions (Python has properties); the values
  are readable through `Problem_get_info` and `disp`.
- `cmd_cluster_legacy` stays (W9e); its three integer reads went through `get_exact_int` with the others.
