## The scope decision (why a new clusterer, not "prune inside k-medoids")

PLAN Task 5.3 registered TADPole-style pruning against the file `pruned_matrix_build.{hpp,cpp}`;
the literature report leaned toward reusing TADPole's pruning *inside* k-medoids (calling the
standalone density-peaks clusterer "niche"). That path is **not admissible** — `[confirmed]` from
source:

- `fast_pam_swap` calls `prob.fillDistanceMatrix()` (fast_pam.cpp:351) then the SWAP loop reads
  `dist_by_ind(x, o)` for EVERY candidate point x over the run — essentially all N² entries.
- MIP / LR-core also require the full dense D in RAM.

A DTW lower/upper bound can only skip a DTW where the consumer never needs exact far-pair
distances — an NN/density search. No existing method qualifies (same wall as the 5.2 reframe). So
the registered band ("labels digit-identical, ≥50% DTW pruned") is only reachable by ADDING a
prunable consumer. Begum KDD 2015 IS density-peaks clustering. **User chose "Add density-peaks
clusterer."** Delivered as `Method::TADPole` (`dtwc/algorithms/tadpole.{hpp,cpp}`); the plan's
`pruned_matrix_build` name became `tadpole` (the pruning is internal to the clusterer).

Note the closure of the 5.2 story: here tighter LBs (Webb/Enhanced, Task 5.2) would prune MORE
(`LB ≥ dc ⇒ skip`), the OPPOSITE of their exact-matrix pessimisation. This clusterer is where
those primitives pay off. (v1 uses symmetric LB_Keogh; wiring Webb/Enhanced in is a later knob.)

## What shipped

`dtwc::algorithms::tadpole(prob, k, dc, prune, stats)` — density-peaks (Rodriguez & Laio, *Science*
2014) with Begum's admissible LB/UB pruning. Cutoff-kernel density ρ_i = |{j≠i : d(i,j) < dc}|
(the only prunable kernel — Gaussian needs every exact distance). Separation δ_i = min distance to
a higher-density point; δ(global densest) = max of the others' δ (Begum Table 2). Centers = top-k
by γ = ρ·δ. Single-pass assignment to the nearest higher-density neighbour. Pruning: `UB < dc ⇒
neighbour`, `LB ≥ dc ⇒ not`, else exact (Begum Table 5 cases A–D); δ step prunes candidate q when
`LB(i,q) ≥ best` (Table 7). UB = no-warp diagonal Σ|x_t−y_t| (equal-length only); LB = symmetric
LB_Keogh reusing per-series envelopes. A strict total order (ρ desc, index asc) makes δ/parents/
γ-ranking/labels deterministic under ρ-ties. Non-Standard/multivariate/NaN variants and
unequal-length pairs fall back to exact DTW (correct, no pruning). Wired: `Problem::cluster()`
dispatch + `Problem::tadpole_dc`; CLI `--method tadpole` + `--dc`; Python `Method.TADPole`.

## Registered bands (fixed BEFORE the runs) + verdicts

- **BAND-ADMISSIBLE [HARD] → CONFIRMED.** `tadpole(prune=true)` and `tadpole(prune=false)` return
  DIGIT-IDENTICAL labels + medoids and total_cost within 1e-9·max(1,cost), over 5 configs
  (N∈{40..60}, k∈{1..5} incl. k>k_true, various dc/band). This is Begum's Theorem 1.
- **BAND-ORACLE [HARD] → CONFIRMED.** `tadpole(prune=true)` labels + medoids EQUAL an INDEPENDENT
  brute-force density-peaks oracle re-implemented in the test (4 configs). Also holds for the
  variable-length fallback path.
- **BAND-BOUNDS [HARD] → CONFIRMED.** For every equal-length pair, LB_Keogh(band) ≤ DTW(band) ≤
  Σ|x−y| (the case-C lower and case-B upper bound). 1225 pairs on N=50, len=40, band=10%.
- **BAND-QUALITY → CONFIRMED.** On two clusters 100 apart (interleaved by index), k=2 recovers the
  exact even/odd ground-truth grouping — a meaningful clusterer, not self-consistent noise.
- **BAND-PRUNE [HARD floor 0.50, `[.]` bench] → CONFIRMED.** N=200, len=64, band=6 (10%),
  dc=24.74 (auto, 2nd percentile): **dtw_calls = 4372 / 19900 pairs → 78.0% pruned** (LB 16000,
  UB 247). Floor ≥50%; paper reports 80–88%. Exact % is advisory (machine/data).

## Honesty notes

- `dtw_calls` counts UNIQUE pairs computed exactly across all stages (density + δ), via a
  first-touch bitset; `pruned_fraction = 1 − dtw_calls/(N(N−1)/2)` = the fraction of brute-force
  DTW work avoided (brute path = 0 by construction).
- The serial pre-trigger computes exactly ONE pair (0,1) to allocate the lazy matrix + bind the
  DTW fn before the parallel region (avoids a `rebind_dtw_fn` race). It is COUNTED (conservative:
  never over-claims pruning). Effect ≤ 1/(N(N−1)/2) — 0.005% at N=200.
- Memory is O(N²) (bounds + first-touch bitset + prob's dense cache) — inherent to TADPole
  ("avoiding all distances" means the EXACT DTW matrix, not the O(n)/pair bounds). Big-N path
  stays CLARA.
