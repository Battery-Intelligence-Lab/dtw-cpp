### Task 1 (T-16 / B-13)

**Question.** Can every CTest entry be gated by a measured execution floor (or an
explicit, declared skip) without lowering any floor and without losing a single
registration, in all four W0 matrices?

**Commands.**

```
cmake -P tests/cmake/test_regex_at_least.cmake
uv run --no-project python scripts/measure_test_floors.py \
  build/highs-1151/w0-baseline-ctest.log build/nollfio/w0-baseline-ctest.log \
  build/arrow-pyarrow-23/w0-baseline-ctest.log build/msvc-debug/w0-baseline-ctest.log \
  --out tests/floors.cmake
cmake -S . -B build/<dir> && cmake --build build/<dir> --parallel
ctest --test-dir build/<dir> --output-on-failure -j1 > build/<dir>/w0-task1-ctest.log
```

**Criterion (fixed before the runs).** All four matrices `100% tests passed`;
CTest inventory unchanged except `test_io_readers` absent where Arrow is OFF and
`cmake_regex_at_least` added; no test without a `PASS_REGULAR_EXPRESSION`; no
floor lowered below its measured baseline value.

**Negative control — the floor bites.**

Raising `DTWC_TEST_FLOOR_unit_test_barycenter` from `"131;14"` to `"1131;14"`
and reconfiguring `build/highs-1151`:

```
$ ctest --test-dir build/highs-1151 -R '^unit_test_barycenter$'
1/1 Test #50: unit_test_barycenter .............***Failed  Required regular expression not found. Regex=[All tests passed \((1131|[2-9][0-9][0-9][0-9]|1[2-9][0-9][0-9]|11[4-9][0-9]|113[2-9]|[1-9][0-9][0-9][0-9][0-9][0-9]*) assertions? in (14|[2-9][0-9]|1[5-9]|[1-9][0-9][0-9][0-9]*) test cases?\)
0% tests passed, 1 tests failed out of 1
```

The binary itself still printed `All tests passed (131 assertions in 14 test
cases)` and exited 0 — only the floor failed it, which is the point. Reverting
the edit and reconfiguring returns `1/1 Test #50: unit_test_barycenter ... Passed`,
`100% tests passed`. `git diff tests/floors.cmake` is empty afterwards.

**Findings.**

- **F-A `unit_test_mpi` is not a Catch2 binary.** It owns `main()`
  (MPI_Init/MPI_Finalize cannot bracket Catch2's main) and prints no Catch2
  summary in any configuration, so no assertion floor exists for it.
  Registered with `MARKER_ONLY` against its own printed line
  (`MPI not enabled (DTWC_ENABLE_MPI=OFF). Skipping MPI tests.`); strictly
  stronger than the baseline, which had no pass/fail regex at all. Only the
  MPI-OFF branch is measured — an MPI-ON build must re-pin the marker.
- **F-B pass 2 re-registered `REQUIRES`-declined tests.** `REQUIRES` returns
  before `add_executable`, so the plan's `NOT TARGET <name>` catch-all guard was
  true for `test_io_readers` and re-registered it with the Arrow-ON floor in an
  Arrow-OFF build (observed: `registered 132`, `test_io_readers` Failed).
  `dtwc_add_test` now records every NAME it handles in `DTWC_TEST_REGISTERED`
  and pass 2 skips those; the plan's own expectation (131, absent) then holds.
- **F-C label change.** `test_cli_rejects_yaml_config` gains the `integration`
  label (`cli` → `integration;cli`), per the plan's Step 3 text. It is the only
  inventory property that differs from baseline; every other label,
  environment, timeout and serial flag is carried over unchanged.
- **F-D `test_pdlp_lp` was a vacuous pass in every HiGHS-OFF build.** Its cases
  called `WARN` + `return`, so a HiGHS-OFF build printed
  `test cases: 3 | 3 passed` / `assertions: - none -` and exited 0 — three cases
  "passing" having asserted nothing, scored green by the old registration's
  absent regex. Fixed at the source: all four sites (including the hidden `[.]`
  bench) now `SKIP("HiGHS is not compiled into this build.")`, the same string
  its four HiGHS siblings use, so the test joins the `_dtwc_highs_skip` list and
  needs no bespoke registration. HiGHS-ON keeps the strict measured 92/3 floor.

**Decision.** Land Tasks 1a+1b+1c as one commit. `cmake/DtwcTest.cmake` is the
single test-registration entry point for Task 2 onward; regenerate
`tests/floors.cmake` from fresh `ctest -V` logs after any deliberate test change.
