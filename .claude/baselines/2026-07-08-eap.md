# EAPruned exact DTW kernel (Task 5.4)

**Date:** 2026-07-08 · **Machine:** dev box, shared/under load · **Build:** build/highs-1151 (clang 18, fast-math on).
**Base commit:** 54a1611 (Task 5.3). **Baseline gate:** 92/92 passed, 0 failed (6 documented skips).

## What shipped

`dtwc::core::dtw_kernel_eap<T,Cost>(n_short, n_long, cost)` — EAPruned exact DTW
(Herrmann & Webb, DMKD 35(6) 2021, arXiv:2102.05221; DTW precursor arXiv:2010.05371).
Unbanded, standard recurrence (min-of-3 + cost). Public shim `dtwc::dtwFull_eap`
(metric-dispatched, L1/SquaredL2). Rolling buffers O(n_short).

**Mechanism.** Seed UB = cost of ONE concrete warping path (the diagonal "L-path":
step diagonally to the corner, then straight along the last short-row, O(n_long)).
Every optimal-path cell has partial_cost ≤ DTW ≤ UB, so pruning any cell whose DP
value exceeds UB never drops an optimal-path cell — the returned value stays EXACT
— while cutting the corners of the cost matrix the diagonal already beats. Per row a
live column window [comp_start, pp) tracks the diagonal; cells below comp_start and
at/after pp are treated as +inf and skipped. No NN cutoff needed → works for an
all-pairs EXACT matrix (unlike LB-based early-abandon, which recomputes on abandon —
the exact-matrix pessimisation documented in the 5.2/5.3 lessons). This is the
exact-matrix DTW-work lever the 5.3 run-log promised for the k-medoids/MIP path.

**Wiring.** `make_standard` (dtw_dispatch.cpp) routes its scalar UNBANDED path
(`p.band < 0`, the DEFAULT since settings::DEFAULT_BAND == -1) through `dtwFull_eap`;
banded builds keep `dtwBanded` (the band already excises the prunable region).
Multivariate + non-Standard variants untouched. No new enum / CLI / Python surface —
EAP is a drop-in faster EXACT kernel for the default matrix build.

## The fast-math correctness fix (bug found + fixed before merge)

First cut returned +inf on ~1/200 random pairs. Root cause: this build compiles with
**-ffast-math** (the `-fno-signaling-nans` warning confirms it). The DP sum and the UB
sum accumulate the same terms in different associations; fast-math reassociation can
make the optimal FINAL cell exceed `ub` by a few ULP → it gets spuriously pruned →
+inf. Fix: prune against a RELAXED threshold `thr = ub·(1 + n_long·16·ε)` (slack
covers worst-case accumulation error over n_long terms). Provably still EXACT:
relaxing the prune only ADDS cells to the computed set — it never removes an
optimal-path cell nor changes the returned recurrence value. (Caught by the
`[eap][exact]` random battery, NOT by the rounded hand-repro — the rounding lost the
triggering precision; lesson logged.)

- **BAND-SPEEDUP [ADVISORY, floor 1.5×, `[.]` bench, WARM timing, order-bias-free] →
  CONFIRMED.** Kernel wall-time `dtwFull_L / dtwFull_eap`, unbanded, lengths

  | regime          | 128   | 256   | 512   | 1024   | cells computed |

  | near-diagonal   | 6.26× | 7.68× | 9.50× | 12.17× | 21% → 11%      |

## Honesty notes

- The "unrelated" regime (random-walk vs independent random-walk, i.e. cross-cluster
  pairs) prunes almost nothing (~98% cells). Its ~1.5× is NOT pruning — it is the
  leaner EAP inner loop (manual min-of-3, no early-abandon row-min bookkeeping) vs
  `dtw_kernel_linear`. Reported as observed; the pruning lever needs near-diagonal
  pairs.
- **Real matrix-build speedup scales with data cohesion.** A dataset with many similar
  (within-cluster) series prunes hard (→ big speedup); an incoherent dataset gets ~the
  leaner-kernel 1.5×. Never worse than plain DP in any measured case, so the wiring
  carries no perf-regression risk.
- Restricted to Standard recurrence + L1/SquaredL2 (the pruning invariant needs
  non-negative edge costs and the standard DP). ADTW/WDTW/Soft/AROW keep their kernels.
- Banded builds (`band ≥ 0`) are NOT routed through EAP: the Sakoe-Chiba band already
  removes the region EAP would prune (Herrmann & Webb §; the two mechanisms overlap).
