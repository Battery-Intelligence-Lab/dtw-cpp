# 2026-09-30 — E1 (W7a/W7b): PAM swap with an O(1) `dist_by_ind`

Question: with `Problem::dist_by_ind` an inlined read of the packed matrix (W7b) instead of an out-of-line call that
re-checked the distance settings on every lookup, does FasterPAM's swap return the same result, and how much faster is it?
Criterion set before the run: counters identical (sweeps, converged, cost bits, a hash of medoids and labels); time
advisory (shared machine: other agents built and tested during the runs).

## Harness [confirmed]

W11a's scratch benchmark (`bench_pam_swap.cpp`, not in the repo): N ∈ {2000, 4000} sine-plus-uniform-noise series of
length 16, `fill_distance_matrix()` once, then `fast_pam_seeded(prob, k, 42, 100)` five times per k ∈ {10, 50};
compiled with the flags of the faster_pam unit test (`-O3 -march=native -flto=thin`, clang 21, MSVC STL) and linked
against the `dtwc++.lib` of the tree under test: base `1fc8776`, head = pb/E1 at the W7b commit. Base and head
alternate (base, head, base, head, base, head); each run prints the counters and the min / median / max of 5 reps.

## Assembly [confirmed]

`fast_pam.cpp` compiled with its `compile_commands.json` flags, without `-flto`, `-S -masm=intel`. Base: the inner loop
of `find_best_swap` (inlined into `swap_phase`) and of `compute_nearest_and_second` call
`?dist_by_ind@Problem@dtwc@@QEAAN_J0@Z` once per element. Head: no call in either loop; the lookup is
`cmp`/`cmovb`/`cmova` (the packed-triangle orientation), `lea`/`imul`/`and`/`shl`, one load. The swap loop keeps the
three vector-pointer reloads it had at base and loads the matrix pointer where base reloaded the `Problem` pointer; the
nearest/second loop runs from registers.

Conclusion: the swap is about 5–6× faster at identical results (the lookup was the loop's cost). Next: a quiet-machine
rerun if a band is ever registered on this number.
