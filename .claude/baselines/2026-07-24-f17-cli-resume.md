## Binding semantics registered before implementation

`--resume` means **completed-result replay**, not iterative continuation:

1. Load `<output>/<name>_checkpoint.bin`, validate it against the current input
   count and requested cluster count, and restore all five result fields.
2. Skip every clustering method. A `converged=false` file is a completed
   iteration-capped result and is replayed as such; `--max-iter` is not an
   additional budget.
3. Rehydrate `Problem` labels, medoids, and cluster count so the ordinary output
   and any already-available scoring route consume the restored result.
4. Do not rewrite the binary source checkpoint during replay.
5. A missing, malformed, or structurally incompatible requested result is a
   nonzero actionable error, never a fresh clustering fallback.
6. Dense directory checkpoints and mmap caches remain independent distance
   persistence mechanisms. Neither requires `--resume`.

PAM-only warm continuation is rejected for F17. It would invent a method-specific
meaning for a generic result file written by every successful method, and the
file lacks enough state to implement the same promise for OneBatchPAM, CLARA,
Lloyd, MIP, LR-core, TADPole, or hierarchical clustering. Streamed assignment
continuation remains explicitly owned by R5/2.1.

Binary v1 cannot authenticate input order, values, configuration, or producing
method. F17 therefore validates shape and fields, then trusts the explicitly
selected `<output>/<name>` result under a documented same-input-order and
same-configuration precondition. Format migration or authenticated provenance
is not silently added to this frozen-format repair.
