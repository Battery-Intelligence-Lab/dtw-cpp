# F15 — portable deterministic-series generator (2026-09-02)

## Outcome

`tests/support/deterministic_series.hpp` no longer uses
`std::uniform_real_distribution`. The four per-toolchain "profiles" in
`tests/unit/unit_test_deterministic_series.cpp` are gone; F15 now registers
**one** SHA-256 + bit pattern per schedule. Verified byte-identical across five
toolchain/flag combinations, including two standard libraries.

## What changed

- `tests/support/deterministic_series.hpp`
  - added `detail::next_signed53(std::mt19937&)` — the classic `genrand_res53`
    schedule (`rng()>>5`, `rng()>>6`), recentred to `[-2^52, 2^52)` in int64;
  - added `detail::scaled(k, scale)` plus two hex literals
    `kUnitScale = 0x1p-52` and `kDecaScale = 0x1.4p-49` (= `10*2^-52` exactly);
  - `benchmark_series` / `benchmark_series_set` → `[-1, 1)`,
    `accelerator_series_set` → `[-10, 10)`; public names/signatures unchanged;
  - `@details` now states the portability guarantee; the "not a portable
    random-data format" sentence is deleted.
- `tests/unit/unit_test_deterministic_series.cpp`
  - deleted `Profile`, `profile_for`, `coherent_profile`, `kRelaxed`,
    `kPrecise`, `kLibstdcxx`, `kLibcxx`, and all `full_hash`/`band0_hash`
    per-compiler DTW hashes (DTW output legitimately depends on FP flags);
  - registers `kScalarHash`/`kRowsHash`/`kAcceleratorHash` +
    `kScalarBits[5]`/`kRowsBits[12]`/`kAcceleratorBits[12]`;
  - the row-seeded case now pins its own 12 bit patterns (it previously only
    pinned a hash);
  - oracle case keeps the same-build `dtwFull_L`/`dtwBanded` vs independent DP
    bit-exact check, with no registered hash;
  - source audit gains a guard that the shared header never reintroduces
    `uniform_real_distribution<`;
  - marker is now
    `F15_TEST_SUPPORT generator=portable scalar=ran row_seeded=ran continuous=ran dense=ran source_audit=ran skips=0`.
- `tests/CMakeLists.txt` — `_f15_focused_regex` updated to the new marker and
  to measured floors **≥177 assertions in ≥6 test cases** (was ≥35 / ≥5).

## Bit-exactness argument (5 lines)

1. `std::mt19937` is specified bit-for-bit by [rand.eng.mers]; only the
   real-valued mapping was implementation-defined, and it is now gone.
2. `hi = rng()>>5` (27 bits) and `lo = rng()>>6` (26 bits) give
   `hi*2^26 + lo < 2^53`: an exact integer, computed in `uint64_t`, no FP.
3. Recentring by `- 2^52` is integer arithmetic; the result `k` satisfies
   `|k| <= 2^52`, so `static_cast<double>(k)` is exact (≤53 significant bits).
4. `k * 0x1p-52` is a power-of-two scaling — exact, no rounding at all;
   `k * 0x1.4p-49` is one IEEE-754 round-to-nearest multiply, which is uniquely
   defined by the standard.
5. Both scales are hexadecimal *literals*, not products, and there is no
   addition anywhere: nothing for `-fassociative-math`/`-freciprocal-math` to
   reassociate and no `a*b+c` for `/fp:contract` or `-ffp-contract` to fuse.

## Proposed CHANGELOG (Unreleased)

- Shared deterministic test/benchmark generators now produce byte-identical
  doubles on every conforming C++20 implementation (exact 53-bit
  `genrand_res53` conversion instead of `std::uniform_real_distribution`);
  F15 registers one fingerprint per schedule instead of four per-toolchain
  profiles. Nominal ranges are `[-1, 1)` and `[-10, 10)`.

## Proposed LESSONS bullet

- `std::mt19937` is bit-exact by the standard; `std::uniform_real_distribution`
  and `std::generate_canonical` are **not** — same seed, different doubles on
  MSVC STL vs libstdc++ vs libc++. Never register a hash over distribution
  output. Convert integers yourself with exact power-of-two arithmetic
  (`(rng()>>5)*2^26 + (rng()>>6)`, then one scale by a hex power-of-two
  literal); avoid `lo + (hi-lo)*u`, which `/fp:contract` and `-ffp-contract`
  turn into an FMA and change the bits. This retires the "add a new profile row
  per compiler" rule in the F15 entry above.
