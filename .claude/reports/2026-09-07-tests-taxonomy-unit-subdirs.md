## 5. Naming and layout

**Files whose name does not match their subject**
- `unit_test_pruned_distance_matrix.cpp:68-223` — 155 lines and 3 TCs of pure lower-bound testing (`LB_Kim basic properties`, `Envelope computation`, `LB_Keogh basic properties`) in a file named for the pruned matrix. This is the *third* copy of that contract, after `unit_test_lower_bounds.cpp` and `test_lower_bounds_adversarial.cpp`.
- `unit_test_pruned_distance_matrix.cpp:1245-1316` — `detail::decode_pair` tests, while `tests/unit/test_decode_pair.cpp` is the SSOT file for that symbol and already carries the same white-box seed-bias technique (`:309`).
- `unit_test_distance_matrix.cpp:153-169` — tests `dtwc::io::to_full_matrix`, an IO function, from a file named for the matrix type.

**Files that belong elsewhere by the code they test**
- `tests/unit/core/unit_test_run_thread_scope.cpp` — subject is `dtwc::run` from the top-level `parallelisation.hpp`, not anything in `dtwc/core/`; `tests/unit/unit_test_parallelisation.cpp` already exists for that header.
- `tests/unit/core/unit_test_invalid_public_selectors.cpp` — six of its eight enums are `dtwc::algorithms::` (`Linkage`, `PAMVariant`, `OneBatchWeighting`, `BarycenterMethod`) or `dtwc::mip::` (`AssignmentMatrixLayout`) subjects, living in `core/`.
- `tests/unit/core/unit_test_distance_matrix_csv.cpp` — the subject is `dtwc::io::write_csv`/`read_csv` and `Result::save`, while `tests/unit/io/` exists and holds one file.
- `tests/unit/core/unit_test_gpu_dtw_common.cpp` — correct by header path (`core/gpu_dtw_common.hpp`) but inconsistent with the six other GPU tests, which all sit flat in `tests/unit/` (`test_cuda_*.cpp`, `test_metal_*.cpp`) alongside the shared `gpu_fixed_band_oracle.hpp`.

**Naming-convention split**
- `core/`, `algorithms/`, `types/` use the `unit_test_` prefix; `mip/` and `io/` use `test_`. The single exception inside `core/` is `test_pruned_openmp_contract.cpp`, which is also the only file in that directory that reads library source text.

**Registration quirks**
- `tests/CMakeLists.txt:1` globs recursively, so any new `.cpp` becomes a CTest target with `SKIP_RETURN_CODE 4` and no gate. There is no opt-in step at which a gate would naturally be added.
- `cmake/Coverage.cmake:31` runs every test with `WORKING_DIRECTORY = ${CMAKE_SOURCE_DIR}`. Two files in scope carry a workaround for exactly this (G14: `unit_test_fast_pam.cpp:33-39`, `unit_test_fast_clara.cpp:38-44`).
- `cmake/Coverage.cmake:8` defines `DTWC_TEST_DATA_DIR` pointing into the source tree. `test_pruned_openmp_contract.cpp:24-25` and `unit_test_mmap_distance_matrix.cpp:212-215` use `path{DTWC_TEST_DATA_DIR}.parent_path()` to locate and **read library source files at run time**. The path is compile-time baked (so this is not a CWD dependency), but both tests fail on any host where the source tree is absent at run time.
- `unit_test_nearest_medoid_assignment` is the only test in scope forced to a specific thread count (`OMP_NUM_THREADS=4`, `PROCESSORS 4`, `tests/CMakeLists.txt:284-289`). `unit_test_pruned_distance_matrix.cpp` instead mutates OpenMP state from inside the test (`:619-627`, `:655-662`, `:723-730`) with no `RUN_SERIAL`, so it can perturb concurrently scheduled tests.

**Portability of fixtures.** Eleven sites in scope seed `std::mt19937`/`std::mt19937_64` and draw through `std::uniform_real_distribution`, `std::uniform_int_distribution` or `std::normal_distribution`, whose mappings are implementation-defined — the exact reason `tests/support/deterministic_series.hpp:6-12` exists: `unit_test_lower_bounds.cpp:109/141`, `unit_test_msm_twe.cpp:100/115`, `unit_test_independent_mv.cpp:121/156`, `unit_test_tadpole.cpp:63-64/320-321`, `unit_test_mmap_data_store.cpp:44-45`, `test_lagrangian_root.cpp:110-111/135-136`, `test_pdlp_lp.cpp:92-93/108-109`, `test_reduced_cost_fixing.cpp:94-95/118-119`, `test_mip_backend_guards.cpp:339-340`. In every one the assertion is an *inequality* or a comparison against an oracle computed on the same data, so no fingerprint is at risk — but these tests exercise **different data on MSVC than on libstdc++**, so a platform-specific defect can hide.
