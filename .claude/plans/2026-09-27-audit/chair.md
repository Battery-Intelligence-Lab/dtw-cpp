# DTWC++ 2.0 — decision document (chair's resolution, 2026-09-27, HEAD cd5d449, read-only)

## 1. Verdict

1. The library becomes what its skeleton already is: `device → load → cluster → Result` in C++/Python/MATLAB/CLI over one `Config`, one `Problem` session with private distance semantics, one distance resolver, one matrix fill per device, one binary matrix file, one names table, one `index_t`. Everything built *beside* that skeleton — second enums, second dispatchers, second readers, second writers, diagnostic modes, research solvers, drift detection, count guards, shims for names nobody was given — goes.
2. Net change [inferred from the digest's per-finding estimates; "was" measured today with `git ls-files | xargs cat | wc -l`]: library (`dtwc/` excl. `extern` 34,163 + `python/` 6,678 + `bindings/matlab/` 4,723 = 45.6k) → ~26k; tests 75.8k (1,693 `TEST_CASE`s) → ~38k; scripts + `.claude/` + `docs/` + CHANGELOG (6.7k + 39.6k + 17.9k + 1.5k = 65.6k) → ~16k. About −108k of 214k tracked lines.
3. Users notice: the default CPU fill gets faster (Pruned and Python's `use_pruning=True` gone, EAP everywhere); Soft-DTW stops holding 0.5 GB/thread; Python/MATLAB gain MSM/TWE pairwise, Parquet/Arrow through `load()`, `set_metric`, one `system_check`; `hpc` ships a config file; four persistence formats become one.
4. Two things change on purpose for v1.0.0 users, both with a shim for one release: `clusters_ind`/`centroids_ind` become `std::vector<index_t>` (Q3) and the v1 CLI spellings return as warn-once aliases (they are silently gone today). `cluster_by_kMedoidsPAM` gets the shim it never had.
5. Every deletion of a 2.0-born name carries a `git grep` proof in its commit; every refactor that claims no-op is held to digit-identical conformance; two deliberate digit changes (Soft-DTW LSE order, v1 one-argument `init::Kmeanspp` sequence) are pre-registered.
