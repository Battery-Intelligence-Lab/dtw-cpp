## 4. `test_config_spellings` on Windows — diagnosis

Mechanism (observed): `dtwc_cl` prints the settings echo with `std::cout << ... "\n"` (`dtwc/dtwc_cl.cpp:41-62`); the test runs the binary through `std::system` with `> stdout.txt` (`test_config_spellings.cpp:167-183`), so the child's text-mode stdout is written as CRLF; `read_text` opens the capture in `std::ios::binary` (`:69`), `lines_of` splits on `'\n'` only (`:74-80`), and `trimmed` strips only `' '` (`:194-198`). So `settings["Device"] == "cpu\r"` while `defaults` comes from in-process `to_config_text` without `\r` — Catch2 prints the expansion as `"cpu" == "cpu"` because the `\r` returns the carriage.

Prediction confirmed against `build/Testing/Temporary/LastTest.log:1786-1849`: the failing lines are 481-484, 486-493, 496, 498-499, 502 — every CHECK that reads the child's stdout (16) — and the two pure-default CHECKs (`:485`, `:497`) pass. The `--help` case in the same file passes because it tokenises with `words >> word` (`:219`), which treats `\r` as whitespace.

Minimal fix, test-only, `lines_of` (`:78`):
```cpp
for (std::string line; std::getline(stream, line);) {
  if (!line.empty() && line.back() == '\r') line.pop_back(); // text-mode stdout on Windows
  lines.push_back(line);
}
```
Expected: `ctest -R test_config_spellings` passes; baseline becomes 137 pass + 5 MAY_SKIP. No production change; `.gitattributes` already forces LF for the fixtures, so the golden path was never affected.
