## 2. Four rules I apply (the owner's words, made operational)

1. **No diagnostic modes in the shipped library.** `Pruned`, `LowerBoundStrategy`, `KernelOverride`, `PAMVariant`, `OneBatchWeighting`, `TADPoleStats`, `pdlp_lp_bound`, `dtw_runtime`: research knobs. A benchmark or a test that needs a forced path gets a `detail::` overload, never a public enum.
2. **A public symbol needs a non-test caller or a documented user.** Test-only public API found by grep: `core::dtw_runtime`/`core::dtw_distance`, `fast_pam_swap`/`PAMVariant`/`FastPAM1Naive`/`FasterPAM`, `lagrangian_root(Problem&)`, `compute_distance_matrix_pruned`, `tadpole(prune=false, stats)`, `dtwc::test::*` (included by both bindings but only to re-export a probe), `pdlp_lp_bound`, `DataLoader::count`/`bulk_read_count`, `softmin_gamma`, `missing_rate`, `TimeSeries[View]`, `MmapDistanceMatrix::open(path)`, `lb_*_valid` traits, the 1-vs-N/K-vs-N GPU entries, `compute_lb_keogh_{cuda,metal}`, `compute_distance_matrix_mpi`. All go or become `detail`.
3. **One of everything.** One index type (`index_t = std::int64_t`), one on-disk N² format, one Arrow→Data converter, one names table, one distance resolver, one run description (`Config`), one system check, one estimator, one method enum, one artefact writer, one style guide, one roadmap.
4. **Guards live in the builder, once.** 46 `validate_*` definitions, 213 calls, 61 `std::logic_error` throws, 36 `INT_MAX` checks, 25 `saturating_*` calls, 53 `require_finite` calls in `dtwc/`. After the cuts: one `validate(DistanceConfig)`, one `validate_fill_request`, one finite scan at each matrix intake, the two-line HiGHS/Gurobi `int` check, and `assert()` for programming errors.

## 5. Where I disagree with a verifier or auditor

- **Per-lookup finite checks (kernels-12, algorithms-mip-04):** the verifier is right that `set_distance_matrix` (Python, MATLAB, the C++ mutable accessor, an mmap open) accepts non-finite values unchecked. That is the reason to add one O(N²) scan at those four intakes in the same change and delete the per-lookup checks in `find_best_swap`; not a reason to "leave it to another slice".
- **`MetricType::L2` (kernels-10):** delete it. No string names it, in univariate kernels it silently equals L1 (a mislabel trap), and nobody asked for per-step Euclidean. Two metrics: `l1`, `squared_euclidean`.
- **`Range`/`Index` (session-surface-13):** zero value; leave the v1 classes alone. Drop the item.
- **llfio → mio (tests-build-14):** agree, do not swap. The real decision is D-18's consequence: every wheel, MEX and release archive builds with `LLFIO=OFF`, so the whole mmap surface is dead for pip users. Either RL-3 ships an llfio-ON wheel, or `use_mmap_distance_matrix` leaves the Python and MATLAB surface. Keeping both is the garbage.
- **`Result.medoid_indices`, `ClusteringResult.medoid_indices`:** delete only the Tier-1 Python alias; the Tier-2 field is canonical and used by three examples (records-docs-03 verifier).
- **hierarchical (algorithms-mip-16):** do only the `fill_distance_matrix()` fix; NN-chain and dropping `max_points` are 2.1 if a user asks.
- **Barycenter k-means** stays (DBA/SSG/Soft-DTW centroids are a real method) but only Python can reach it; either add it to `ClusterMethod` so `Config`/CLI/MATLAB see it, or document it as Tier-2 Python-only. Trim only the scaffolding (algorithms-mip-12).

## 7. Invariants touched, and why they survive

Everything else is required to be conformance digit-identical.
