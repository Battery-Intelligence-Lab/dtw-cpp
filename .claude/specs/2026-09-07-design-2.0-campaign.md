Status: APPROVED 2026-09-07 by Volkan ("Go"): every III.10 recommendation adopted
as the decision (outcomes recorded under III.10); W0 executes from
`.claude/plans/2026-09-07-w0-baseline-tooling.md` subagent-driven. Part II was

were read, so that Part III is an honest diff.

`Problem` signatures used by Python/MATLAB frozen this campaign; break other
public API freely but never "just to break"; tests may be deleted/merged with

concern and existing no-copy structures are not to be reverted; small steps;
separate branch if the work would break `Claude`; spec checked before code.

### I.3 What is wrong (headline, all confirmed at HEAD)

1. **Layering exists on paper only.** `core/` includes `Problem.hpp` (public signature of
   the pruned builder and `resolve_dtw_fn`), `Data.hpp`, `warping*.hpp`, `distance.hpp`
   (cycle-shaped); `error.hpp`/`missing_utils.hpp`/`settings.hpp` are stdlib-only
   foundation living *above* `core/`; `algorithms/` and `mip/` consume 33 `Problem`
   members and `fast_clara` constructs `Problem`s.
2. **Three resolvers for "which variant means what"** (`resolve_dtw_fn`,
   `distance::dtw(params)`, `dtw_runtime`) that already disagree; `DTWVariant` guarded in
   five places; the orientation preamble copied 12×.
3. **The hot lookup pays for the API's openness.** Because `Problem`'s configuration
   fields are public and the closure reads them live, every O(1) `dist_by_ind` runs
   ~30–40 validation branches, one preflight *twice* (the comment says once), an
   O(N²) `is_distance_matrix_filled()` per Lloyd iteration, and a DCL without a fence.
   `distanceInClusters()` re-issues ≈N²/2k already-cached lookups per iteration.
4. **Results leave algorithms through a side channel.** Six algorithms write
   `prob.clusters_ind`/`centroids_ind` directly and non-transactionally, barycenter
   writes nothing, the MIP backends use a validating transaction; Tier-1 `Result`
   silently depends on the writeback. `Method` names 4 of 10 algorithms.
5. **Duplication where it costs correctness.** Balinski model ×3 with mirrored
   index conventions (equivalent only while D is symmetric); pruned fill ×2 with
   drifted feature sets and different parallel shapes; artefact writers ×2 compatible
   + 1 incompatible; Arrow status checkers ×3; CSV loop ×3; CMake test-gate block ×13
   with four skip regexes; `hierarchical`/`tadpole` publish `total_cost` through an
   unguarded `+=` that the other algorithms replaced after a NaN bug.
6. **Silent-wrong-answer edges still open**: `-fno-finite-math-only` is `PRIVATE`
   (a `-ffast-math` consumer gets wrong AROW/ZeroCost); CLI output streams never
   close-checked (full disk ⇒ truncated labels, exit 0); truncated `--dist-matrix`
   half-fills the matrix and continues; `Auto` picks `Pruned`, proven to do strictly
   more work than BruteForce on an exact matrix; brute-force fill decomposes by row
   (triangular load) while the pruned path already uses balanced pair blocks.
7. **Dead weight**: ~180 lines of tested-but-unwired MV lower bounds, `TimeSeries[View]`,
   dead overloads, `sync()`s, a `Float32+Mmap` combination declared but unimplemented,
   test instrumentation compiled into the loader, a test-only `friend`, unreachable
   branches, stale comments naming files that do not exist, README claims (HDF5,
   `dtwc_main` arguments) the code cannot honour.
8. **Build/CI gaps**: no leg builds with all optional deps OFF (non-negotiable #3
   is not gated); warnings are empty in every CI build; sanitizer plumbing bypassed;
   Gurobi probed on every configure; option prefixes split `DTWC_`/`dtwc_`;
   `THIRD_PARTY_LICENSES.md` names one of ~8 statically included components.

## Part II — Ideal design, derived first

Written before the maps were read and left as written; III.0 records where the as-is
corrected it (the `warping*` wrappers, the nearest-medoid scans, `std::function`
binding, `Pruned`).

### II.1 Quality goals, in priority order

1. **Fastest DTW clustering for large N.** Kernels are latency/memory-bound;
   the parallel fill is lock-free by non-overlapping decomposition; scratch is
   thread_local (resize, never shrink); series are viewed, never copied;
   variant/metric selection is compile-time inside kernels and type-erased
   exactly once per session, never per call.
2. **Provably correct.** Every algorithm has a written derivation and an
   independent oracle; refactors are proven by digit-identical outputs, not by
   inspection.
3. **Cross-language consistent** (CasADi model): the C++ surface is the
   contract; Python/MATLAB mirror names and semantics.
4. **A joy to develop.** Small units with one purpose, dependencies only
   downward, rules that are *checked* (by configure-time or ctest guards) rather
   than remembered, a handful of composable helpers instead of copied loops.
5. **Optional dependencies stay optional**; the core builds and tests with all
   of them OFF; no silent fallbacks.

### II.2 Layer model (includes only point downward; enforced by a check)

| Layer | Contents | May include |
| --- | --- | --- |
| L0 `base` | element types, `Index`/`Range`, error taxonomy, settings/constants, parallel primitives (`run_openmp`, pair decomposition, per-thread reduction), memory (thread_local scratch, allocation hooks), timing, portable RNG, functional helpers | std only |
| L1 `core` | DTW kernels + Cost/Cell policies, variants (ADTW/WDTW/DDTW/soft/missing), lower bounds, `SeriesView`, distance-oracle concepts, distance matrices (dense, mmap, pruned fill), z-normalise, `ClusteringResult` value types, medoid assignment policy | L0 |
| L2 `algorithms` | PAM/FastPAM, CLARA, CLARANS, OneBatchPAM, TADPole, hierarchical, barycenters — templated on a distance oracle, emit `ClusteringResult` | L0, L1 |
| L2' `mip` | Balinski model description (built once), solver adapters (HiGHS, Gurobi), Benders, LR-core, PDLP; warm start consumes L2 | L0, L1, L2 |
| L3 `session` | `Problem` façade: owns `Data`, `DtwBinding`, `DistanceCache` (+ configuration fingerprint), `ClusterState`, settings; method dispatch table; checkpoint identity | L0–L2' |
| L4 `io` | loaders (CSV/Parquet/Arrow/dtws), matrix IO, ONE artefact-writer module, config file (TOML/YAML via CLI11) | L0–L3 |
| L5 `surface` | Tier-1 `api` (Dataset/load/cluster/Result), CLI (parse → settings → session → writers, thin), capability probes | L0–L4 |
| backends | `cuda/`, `metal/`, `mpi/` — implement a filler interface over L1 matrices | L0, L1 |

Rules: (a) L1 never names `Problem`, `Data`, or a loader; (b) algorithms take
an oracle + options and return a value — they do not write `Problem` members;
(c) one writer per artefact; (d) strings become enums at the surface, never
below it; (e) every optional dependency has its guard OUTSIDE its `#ifdef`.

The layer manifest is a file→layer table checked at configure time (same
mechanism as the header `omp critical` guard); the generated include graph
(Doxygen `HAVE_DOT`) is published with the docs.

### II.3 Core interfaces

+ `SeriesView`: `std::span<const T>` + ndim, the only way series cross a layer.
+ `DistanceFn` concept: `std::invocable<F, SeriesView, SeriesView>` returning a
  floating type. Kernels are templated on Cost/Cell policies; the session binds
  the chosen variant into ONE `std::function` (as today — deliberate).
+ `DistanceOracle` concept: `size()`, `operator()(i, j)`, optionally
  `row(i)` (contiguous span for cached scans) and `is_cached(i, j)`. Satisfied
  by dense and mmap matrices and by a lazy session view (computes on miss, no
  copy). Algorithms are templated on it: zero overhead, fakeable in tests, and
  the seven nearest-medoid copies collapse into one
  `assign_to_nearest(oracle, medoids, labels)`.
+ `ClusteringResult` (exists) is the single output of every algorithm.
+ `MipModel`: one Balinski builder producing an index-convention-free model
  consumed by both solver adapters.
+ `Filler` policy: dense / pruned / GPU / MPI fillers write into a matrix sink
  with non-overlapping regions; the session picks one.

### II.4 Functional helpers (few; each must delete ≥2 copies to earn its place)

+ `parallel::for_each_index(n, f)` (= `run_openmp`), `parallel::for_each_pair(n, f)`
  (lock-free pair decomposition, exposed), `parallel::reduce(n, init, f, op)`
  with per-thread slots and the existing exception capture.
+ `visit_variant(params, f)`: runtime `DTWVariantParams` → a call of `f` with
  the concrete policy types (one dispatch table instead of several switches).
+ `expect(cond, Error, msg)`, `checked_cast<To>(x)`, `finally(f)`.
+ Strong types where a bug class exists (`Delimiter{','}` instead of the
  poisoned `load` overloads).

### II.5 Error model

Typed exceptions (existing taxonomy, contract §5) at API boundaries;
`noexcept` truthful (a `noexcept` move that can throw is a defect); no
exceptions as control flow in parse or hot paths (`from_chars`-style results).
`tl::expected` is adopted only if the ledger shows ≥3 bool+out-param sites.

### II.6 Performance rules that are checked, not remembered

+ No lock in a hot path: an allow-list of named criticals with a one-line
  justification each; anything else fails configure.
+ No allocation inside kernel loops: the allocation-counting fixture becomes a
  shared test utility and guards every kernel and swap loop.
+ Machine-independent counters (cells computed, LB prune rate, swaps
  evaluated) have registered bands; wall-clock is advisory.
+ Refactor-only claims require digit-identical conformance outputs.
+ Data is never copied across layers.

### II.7 Test architecture

Layout mirrors the layers (`tests/base … tests/api`) plus `conformance`,
`adversarial`, `perf`. One shared support library (fixtures, generators,
allocation guard, tolerant matchers). Every file opens with the contract it
pins and the oracle it uses. Categories: contract/oracle (keep), adversarial
(keep), fingerprint (keep, tolerance where cross-compiler), implementation
detail (rewrite as contract or delete with coverage proof), trivial (delete).

### II.8 Documentation

Doxygen groups per layer, `@ingroup` on every public entity, generated include
graph, `design.md` reduced to the layer contract + a link here,
`api-contract-2.0.md` stays the freeze artifact and receives addenda through
its governance process.

### II.9 Libraries

Keep: Catch2, CLI11, fkYAML, HiGHS, nanobind, llfio, nanoarrow, Google
Benchmark. Candidates, each admitted only against ledger evidence: `{fmt}` (MIT;
`std::format` is absent on GCC 11/Clang 14–16/older libc++ in CI), `tl::expected`
(CC0). Rejected for YAGNI: mdspan (one dense matrix class), range-v3 (partial
`std::ranges` on the CI floor; no ranges in hot loops anyway).

### II.10 Compiler floor

GCC 11/12, Clang 14–17, Apple Clang (macos-latest), MSVC 19.3x+ — the CI
matrix. Usable: concepts, `std::span`, `std::bit_cast`, `<numbers>`, constexpr
containers. Not usable without polyfill: `std::format`, `std::jthread`, full
`std::ranges`, `std::atomic_ref` (libc++ < 19).

## Part III — The target: ideal diffed against as-is

Row-level verdicts live in `.claude/specs/2026-09-07-diff-ledger.md` (C-, O-, A-,
B-, T-, G- IDs). This part states the resulting design, what the diff changed in the
ideal, and the decisions that are Volkan's.

### III.0 Where the as-is corrected the ideal

+ The `warping*.hpp` family is **not** a legacy duplicate of `core/dtw_kernel.hpp`; it
  is the thin wrapper layer over one kernel family. It stays. What goes is the 12×
  orientation preamble (C-03) and the three resolvers (C-02).
+ The seven nearest-medoid scans are kept apart for a reason (different index spaces,
  distance signatures and side effects; a runtime policy branch would enter the hottest
  loops). The ideal's single `assign_to_nearest` becomes: a *template* helper adopted
  only where the object code stays byte-identical (A-18).
+ `std::function` binding per Problem stays (P1/P12). The change is *what the closure
  captures* — a value, not `*this` (C-01, O-02) — not the erasure itself.
+ Deferred N² allocation, the serial pre-scan, the guard order in the fill and the
  two-tier cache identity are all deliberate (P10–P14). The hot-path cost that goes is
  the redundant *validation*, not the mechanisms.
+ `Pruned` is a diagnostic/NN tool, not a default candidate: LESSONS.md:160 proves it
  does strictly more work on an exact matrix (C-05).

### III.1 Layers, made checkable (C-11, C-12, C-01, C-04, A-13, B-12)

```text
base/      error, settings, types, index/range, parallel (run_openmp, for_each_pair,
           reduce), memory (scratch, allocation hooks), timing, portable_random,
           checked_cast, expect, saturating arithmetic
core/      kernels + policies, variants, orient(), dispatch table (visit_variant),
           DistanceConfig, lower bounds, SeriesSource/DistanceOracle concepts,
           dense/mmap matrices, ONE pruned fill, ClusteringResult, assignment policy
algorithms/, mip/   templated on the oracle; return values; MipModel once
session/   Problem (façade) = Data + DistanceCache{binding, matrix, identity}
           + ClusterState + settings; checkpoint identity
io/        loaders, matrix IO (dense and mmap split), ONE artefact-writer module,
           config file
api/, cli/ Tier-1 (Dataset/load/cluster/Result), capabilities.hpp, thin CLI
cuda/ metal/ mpi/   fillers over core matrices; depend on base+core only
```

+ A `file → layer` manifest in `dtwc/CMakeLists.txt`, checked at configure time with the
  same mechanism as the header-critical scanner: any `#include` that points upward fails
  the configure. The Doxygen include graph is generated from the same tree.
+ Physical moves (foundation headers into `base/`, `dtwc::solver` types into `mip/`) are
  ONE mechanical wave driven by a script, with a compatibility umbrella so the bindings'
  two include lines and the tests keep compiling. **DECIDE C-11**: do the moves (recommended:
  the graph becomes acyclic by construction) or enforce by manifest only.
+ `core/` stops naming `Problem` and `Data`: `resolve_dtw_fn(DistanceConfig, const
  WdtwWeightCache&)`, `fill_distance_matrix_pruned(SeriesSource, sink, PrunedOptions)`,
  `MmapDataStore::create(n, ndim, span-of-spans)`.

### III.2 Distance binding and dispatch (C-01, C-02, C-03, C-13, C-14, C-19, C-22, O-02, O-24)

+ `DistanceConfig{variant_params, band, missing_strategy, ndim, precision}` is a value
  with a fingerprint. `resolve_dtw_fn` captures it *by value*; the closure is a pure
  function of the config. A raw write to a public field is detected at the next gateway
  (`fill`, `cluster`, `scores::*`, oracle open) by the existing snapshot compare and
  triggers a rebind — the semantics `ensure_dtw_function_configuration_current` already
  enforces, now the only semantics. `dtw_binding_owner_` and the relocation repair
  retire because nothing captures `this` (a use-after-move test stays).
+ One dispatch table: `core::visit_variant(config, f)` maps the runtime config to the
  concrete Cost/Cell/kernel types once. `resolve_dtw_fn` builds its closure through it;
  `distance::dtw(...)` and `dtw_runtime` call the kernel through it directly (no
  `std::function` construction on one-shot paths). Validation is one table next to it.
  An equivalence test drives fill-vs-facade on every variant×missing pair.
+ `core::orient(x, y)` returns the 4-field short/long aggregate; the callable stays a
  template parameter (DNB-1/2).
+ **Custom distance (new, small):** `Problem::set_distance_function(dtw_fn_t)` (additive).
  Consequences designed in: the WDTW cache is bypassed, the mmap cache identity carries
  a `custom` tag so a cached matrix from a built-in variant is never served to a custom
  function (or mmap caching is refused for custom functions — DECIDE, recommend refuse).
  The compile-time path (Cost/Cell policies) is documented as the C++ extension API with
  one worked example.
+ **DECIDE C-19**: wire `MetricType::L2` to a token (`l2`/`euclidean`) or delete
  `MVL2Dist`. Recommend wire.
+ `-fno-finite-math-only` becomes PUBLIC for GNU/Clang front-ends (C-08); a consumer-build
  test compiles a client with `-ffast-math` and runs the AROW tests.

### III.3 The distance matrix and its fill (C-04, C-05, C-06, C-07, C-09, C-20, C-21, O-08, O-13)

+ One pruned fill over `SeriesSource` + sink, with the pair-block decomposition; the
  standalone copy and its false-sharing reduction die.
+ The brute-force fill adopts the pair-block decomposition through
  `base::parallel::for_each_pair` (balanced load; writes stay disjoint; digit-identical).
+ `visit_distmat` is hoisted out of the pair loop (once per block, not twice per pair).
  The mmap digest cost is a documented, measured trade-off: W0 registers the first
  benchmark of dense vs mmap `set()` under contention; batching digests per row is
  DEFERRED to that evidence.
+ **DECIDE C-05**: `Auto` resolves to BruteForce for exact matrices; `Pruned` stays an
  explicit strategy (TADPole/NN uses). Band: cells computed + digit-identical matrix.
  **DECIDE C-09**: with that, the ~180 lines of unwired MV lower bounds are either wired
  (then tested from a public path) or deleted with `docs/content/method/multivariate.md`
  corrected. Recommend delete unless a consumer is named.
+ The lazy `dist_by_ind` initialisation gets a correct DCL: `std::atomic<bool>
  matrix_ready_` (acquire fast path; release under the named critical, which now only
  resizes); binding happens at the gateway. Deferred allocation (P10) is preserved; the
  three hand-rolled "prime serially" sites collapse into one seam (A-23).
+ `filled` becomes O(1) state (a counter), not an O(N²) NaN scan; `Result::distance_matrix()`
  reads the packed matrix directly.
+ Dense matrix CSV IO no longer drags llfio (header split); mmap v1/v2 migration strings
  for never-produced files go.

### III.4 Algorithms and MIP (A-01 … A-25, O-03)

+ **Oracle, not `Problem`.** Each algorithm is templated on a `DistanceOracle`
  (`size()`, `d(i,j)`, `row(i)` where cached) plus a `SeriesSource` where it computes
  DTW directly, and takes an options struct. `Problem::oracle()` is the view. CLARA's
  subsample becomes a sub-oracle over an index map — no `Problem` construction. Zero
  overhead by construction; fakeable in tests. Done one algorithm per task, conformance
  and fingerprints as the oracle, the `0af4cbd` byte-identical-object test where a task
  claims no-op.
+ **Values out, one publish path.** Every clustering algorithm returns
  `ClusteringResult`; `Problem` publishes through the one validating transaction. The
  three "run a heuristic unpublished" mechanisms, the `friend` for Benders and the raw
  writeback Tier-1 relies on all disappear.
+ **One `Method`.** The enum names every shipped algorithm (additive); one
  string↔enum table in `enums/Method.hpp` serves Tier-1, CLI and bindings;
  `Problem::cluster()` can reach FastPAM.
+ **One numeric contract.** `hierarchical`/`tadpole` publish `total_cost` through
  `OrderedMedoidObjective`; `checked_point_count()` everywhere; `InvalidInput` everywhere;
  Benders throws instead of printing; trivial k handled once at the publish layer;
  `BendersMode`/PDLP variant as enums below the surface.
+ **One Balinski model.** `MipModel` (layout-free) feeds the HiGHS and Gurobi adapters
  and the PDLP arbiter; precondition "D symmetric" stated and debug-asserted.
+ **Options compose** (`BarycenterClusteringOptions` contains `BarycenterOptions`; one
  `validate()` per struct). Reachability of LR/CLARANS knobs is an interface decision →
  next campaign.
+ **RNG**: unseeded entry points draw one seed from a thread-safe source and call the
  seeded path; the process-global engine remains only for the documented legacy Tier-2
  `init::random`. `one_batch_pam`'s mutex + `cerr` become a stats field.
+ KEEP: sequential `find_best_swap`, serial FasterPAM sweep, hoisted per-thread scratch,
  named `.cpp` criticals, algorithm-owned scans, barycenter's own path-returning DP
  (documented as the one known semantic duplicate), `fast_pam`'s BUILD save/restore
  (now documented and tested as a strong exception guarantee), CLARANS (validated and
  UB-fixed; keep/delete is an interface decision with a benchmark).

### III.5 The session: `Problem` behind its frozen surface (O-01 … O-24)

+ No frozen member is private, so `Problem` decomposes behind unchanged setters:
  `DistanceCache` owns binding, matrix, identity and the snapshot; `ClusterState` owns
  `Nc`, labels, medoids, method and the transaction; `Data` ownership stays as is.
+ Hot path after the change: `dist_by_ind` = snapshot compare (O(1)) → packed lookup →
  compute-on-miss through the bound closure. No preflight on the fast path; the full
  validation runs at gateways and on snapshot drift.
+ `Data` gets one `Storage` enum {HeapF64, HeapF32, View, MetadataOnly} replacing three
  independent booleans (same predictable branch, exact state space).
+ Deleted: `distanceInClusters()`; the test-only `friend`; `s_bulk_read_invocations`
  (replaced by an optional `LoadStats*` out-parameter, the `PruningStats` pattern);
  unreachable checkpoint branches; the relocation-repair machinery (O-24).
+ Fixed: `set_data` resizes label buffers like `set_view_data`; `set_max_iter`/
  `set_n_repetitions` reject `< 1`; `writeMedoids` uses the checked writer; loader
  takes the device explicitly (env-reading overload delegates); const getters.
+ **DECIDE O-09**: one `io::artefacts` module for Tier-1, CLI and `Problem::write_*`.
  `Problem_IO`'s 1.x filenames (`_Nc_<k>.csv`, `medoids_rep_<r>.csv`, …) are dropped
  (contract addendum) or kept as a legacy writer. Recommend drop: `Result::save`'s
  four-file contract is the documented one and the CLI already matches it.
+ Contract addendum: `checkpoint` as the 12th public field (O-20).

### III.6 IO and CLI (B-01 … B-11, B-20, B-21)

+ CLI = parse (CLI11 transformers straight into enums; `CLI::Range` wherever a range is
  documented) → `CliConfig` value → `InputKind` resolved once (one `switch`, unbuilt
  kinds throw the "built without" message; `.h5` rejected with the conversion hint) →
