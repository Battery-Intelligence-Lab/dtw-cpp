# DTWC++ 2.0.0rc1 release notes

This release candidate completes the 2.0 API, algorithm, packaging, and
documentation work. It is deliberately not the final `v2.0.0` release: tags
and real PyPI publication remain release-operator actions and require explicit
approval after the remote matrices have run.

## Platform status

- **CPU:** validated with Clang 21/OpenMP 5.1 and MSVC 19.50. Python wheels use
  MSVC `/openmp:experimental`; the installed-wheel probe engaged 24 threads.
- **Python:** the Windows CPython 3.13 wheel is 2.25 MB, bundles HiGHS, and
  completed a real MIP solve in a clean environment. CI defines CPython
  3.9--3.14 wheels for Linux x86_64/aarch64, macOS arm64, and Windows amd64.
- **MATLAB:** the local MSVC/OpenMP MEX passed all 61 tests and engaged 24
  threads. CI builds MEX artifacts instead of keeping stale binaries in git.
- **Metal:** source and 64-bit pair-offset changes are build-inspected and
  covered by host arithmetic tests; runtime verification remains a macOS
  release gate.
- **HPC:** the device/API and transport validation are **BETA**. A real Oxford
  ARC end-to-end submission remains an operator gate; local calls fail loudly
  with setup/transport guidance instead of returning a fabricated result.

## Release gates

Local native, Python, MATLAB, documentation, wheel, sdist, and archive gates
are green. The final release operator must still run the hosted wheel/MEX/
archive matrices, perform the quiet-host performance spot check, approve the
tag, and explicitly authorize real PyPI publication. The workflows cannot
publish merely because a tag was pushed: production publication has a manual
confirmation guard.
